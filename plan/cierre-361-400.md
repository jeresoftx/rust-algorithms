# Cierre 361-400: práctica final, repaso y revisión humana

**Estado:** bloque preparado; no representa soluciones implementadas, contenido
revisado ni contenido publicado.

**Trazabilidad:** [issue #11](https://github.com/jeresoftx/rust-algorithms/issues/11).

El último tramo del horizonte no convierte la numeración en una afirmación de
dominio. Combina práctica selectiva con repeticiones de alto riesgo y evidencia
para una revisión humana real. Una solución que no tiene tests, complejidad o
retro no se vuelve válida por ocupar el lugar 400.

## Concepto

El cierre de una ruta de práctica debe transformar experiencia dispersa en
criterio observable. Eso implica elegir algunos problemas nuevos por señal,
repetir errores críticos sin consultar la solución anterior y producir una
lista de lo que todavía necesita juicio humano.

## Problema

El conteo puede ocultar deuda: problemas planeados pero no ejecutados,
simulacros sin retro, tests que no cubren una invariante o explicaciones que no
defienden la estructura elegida. Un cierre útil debe hacer esa deuda visible.

## Alternativas

1. **Completar cuarenta enunciados nuevos.** Maximiza variedad, pero diluye la
   señal de repaso antes de una revisión.
2. **Repetir solo problemas cómodos.** Da fluidez aparente, pero no ataca
   riesgos conocidos.
3. **Combinar candidatos finales, repeticiones dirigidas y auditoría de
   evidencia.** Deja un cierre honesto y auditable.

Se adopta la tercera alternativa.

## Regla de ejecución

Para 361-390, seguir TDD: escribir caso normal, borde y mínimo antes de la
implementación; hacer la solución mínima clara; refactorizar solo para mejorar
la lectura; registrar complejidad y retro. Para 391-400, no inventar evidencia:
anotar lo que se revisó, qué falta y qué requiere validación humana.

## Lista de material para revisión humana

Antes de usar cualquier resultado como contenido del curso, revisar:

- selección final de candidatos y si todavía aporta señal pedagógica;
- exactitud de complejidad y de las invariantes declaradas;
- claridad del Rust y suficiencia de tests para cada implementación nueva;
- calidad de explicaciones, diagramas o ejemplos que se propongan publicar;
- diferencias entre plan preparado, práctica ejecutada y contenido publicado;
- si el horizonte 400 sigue siendo una ruta útil o requiere una nueva decisión.

## Criterio de salida

Este bloque deja la documentación y la revisión futura preparadas. No permite
declarar 400 problemas implementados, cerrar una revisión humana inexistente ni
publicar capítulos. El reporte del issue #13 consolidará esta evidencia para
que la revisión semanal decida el siguiente paso.
